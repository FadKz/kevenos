# KevenOS Participant rehearsal

## Registration Desk review

Open http://127.0.0.1:18155/?access=registration on the local review machine. Select **Registration** and enter the synthetic password `Synthetic-Registration9!`. The desk contains sample teams and one checked-in walk-in. Admin can create individual Registration accounts from **People → Passwords** in Live mode, then use those same desk accounts in Rehearsal. Give each operator the dedicated Registration sign-in link.

1. **Before doors open:** Confirm team capacity and station assignments with Admin. Review the waiting and incomplete-team filters and agree who handles exceptions.
2. **At arrival:** Search by name, partner, or team. Check the person in, confirm their team and station, and tell them to wait for their round. Register walk-ins in open slots. Correct typos, move people into open slots, or swap members of full teams before judging starts. Check-in follows the person.
3. **Hand off access:** Open **Sign-in QR** on the desk screen and let that participant scan it privately. Ask them to show their Participant page and confirm their name and team. The code can be used once within five minutes. Generate a fresh code for a retry. Use an issued typed password when a camera is unavailable.
4. **Handle exceptions:** Filter for no-shows, missing teammates, or people who still need access. Confirm identity before resetting a password or revoking access. Issue fresh access after a move or swap. Once judging starts or a team has a score, send composition changes to the Scoring Desk.
5. **Close the arrival window:** Tell the Organizer how many checked in and which teams are incomplete. Leave the desk available for late arrivals and sign-in help.

QR links carry a temporary sign-in token. They leave existing participant passwords in place and are generated by KevenOS. The token is kept out of the request URL and tied to the current workspace and password revision. Registration accounts can manage participants and check-ins. The Scoring Desk retains control of timers and scores, and Admin manages staff and system access.

The browser rehearsal exercises registration sign-in, walk-in check-in, QR display, mobile redemption and reuse rejection. It uses the link encoded in the QR in an isolated mobile browser session. Physical camera scanning remains a deployment rehearsal check.

To rerun the registration browser journey, set `KEVENOS_REGISTRATION_ONLY=1` when running the command below.

It covers shared cues, conflicting edits, the judge clock, a disconnected phone, private release and the nomination handoff. Run it from this directory with Node and Chrome installed:

```sh
KEVENOS_TEST_PYTHON=/path/to/python-with-agent-requirements \
KEVENOS_SHOTS=/path/to/rehearsal-screenshots \
node tests/test_participant_rehearsal.mjs
```

The participant and judge devices in this test are emulated Chrome viewports. Physical handsets and Safari need their own check if included in the final rehearsal.
